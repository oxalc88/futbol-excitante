# Gauntlet 0.13.1 — executable product-first recovery

Corrects the 0.13.0 deadlock reported after legacy incident migration, without changing application or gameplay code.

- Preserve zero-check certification refusals as visible attempts/debt rather than replacing an evidenced failure classification. No missing bootstrap, UNKNOWN result, product failure or invalid evidence is waived.
- Make packet generation distinct from actual engineering dispatch. The existing OMP adapter can invoke an authorized installed Codex CLI automatically in a native isolated worktree; the core remains harness-neutral and validates the proposal independently.
- Require the exact published original incident baseline for a repair worker, or current evidence for read-only review, before consuming the single dispatch. Integrating the repair preserves intervening product progress. Spent machinery work allows only read-only engineering review.
- Permit bounded, relevant test-startup/native-pool machinery repairs while freezing assertions, coverage, commands, environment overrides, timeouts, retries and policy. Reject side effects hidden in spawn options. Audit rejected repair proposals so a formally open slot cannot cause an endless stop-refusal loop.
- A refused canonical stop is not a stop. Harnesses must perform the deterministic continuation action without asking for routine incident retirement, Codex invocation or publication permission.

No new scheduler, workflow framework, retry controller, recovery budget or notification mechanism is added. Incident history is append-only; no FAIL becomes PASS. Full-required candidates, the fifth uncertified objective, exact milestone/release targets, reviews, evidence and provenance retain their barriers.

Regression coverage executes a native engineer fixture through the actual OMP tool, then material-repair validation and the one full verification reservation. It covers real worker/unknown/product failures followed by zero-check refusal, legacy UNKNOWN without a bootstrap, protected transport/configuration negatives, isolated execution and single dispatch. This fixture does not claim the user's installed Codex/server environment was tested, or confer repository certification.
